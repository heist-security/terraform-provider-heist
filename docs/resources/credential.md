# heist_credential (Resource)

A test account Heist signs in with. Set `type` and the block for that type. The credential is created without application links. Only a new `basic` password (BASIC and HTTP_BASIC) and the instructions and secrets of a CUSTOM credential are updated in place. Any other change, including `type`, replaces the credential, which also removes its application links. Secrets are write-only and need Terraform 1.11 or later.

## Example Usage

```terraform
variable "admin_password" {
  type      = string
  sensitive = true
}

variable "totp_seed" {
  type      = string
  sensitive = true
}

# An existing username and password account. Change password_wo_version
# to send a new password.
resource "heist_credential" "admin" {
  type      = "BASIC"
  login_url = "https://app.example.com/login"

  basic {
    username            = "admin@example.com"
    password_wo         = var.admin_password
    password_wo_version = 1
  }
}

# A custom sign-in flow. Heist generates the email address when it is unset.
resource "heist_credential" "sso_user" {
  type         = "CUSTOM"
  login_url    = "https://app.example.com/sso"
  instructions = "Sign in with the email address, then enter the code from the TOTP secret."

  custom {
    secrets_wo_version = 1

    secret {
      name     = "TOTP"
      value_wo = var.totp_seed
    }
  }
}
```

## Secrets

Secrets are [write-only attributes](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments),
with names ending in `_wo`, so they need Terraform 1.11 or later. Terraform passes them to the provider but never
stores them in plan or state.

Terraform can't compare a write-only value with its previous value, so a changed secret is detected through the
`*_wo_version` attribute next to it. Change the version, for example by incrementing it, to send the secrets again:

- `basic.password_wo_version` sets the new password in place.
- `custom.secrets_wo_version` sets every `custom.secret` value in place.
- Every other version, including `custom_headers_wo_version`, replaces the credential.

Changing a secret without changing its version does nothing. A `custom.secret` with a new name is sent without a
version change, and the values of existing secrets are kept.

The Heist API never returns secrets, so the provider can't detect a password or other secret changed outside
Terraform. Refresh, import and the data sources read only safe metadata, such as the username, email, phone,
masked API key and secret names, which appear in `hint`.

## Generated email and phone

EMAIL, MICROSOFT and CUSTOM credentials sign in with a Heist email address, and SMS credentials with a Heist phone
number. If you don't set one, the provider requests an available one from Heist when it creates the credential and
keeps it in state. Heist also assigns an available phone to a CUSTOM credential that doesn't set one. Later applies
don't request another. Changing the email or phone of a CUSTOM credential replaces it, because Heist keeps the
contact details of an existing CUSTOM credential.

## Application links

The credential is created without application links. Link it to applications separately. Replacing or destroying
the credential removes its links.

## Import

Import is supported using the following syntax:

```shell
terraform import heist_credential.admin 3f6c2a1b-7d4e-4c8a-9b0f-1e2d3c4b5a69
```

The API doesn't return secrets, `*_wo_version` attributes, `custom_header` blocks, `api_key.header_prefix`, or
`oauth2.client_auth_method`, `oauth2.header_name` and `oauth2.header_prefix`, so they are null after import. The
first apply after import records their configured values without changing the credential, so make sure they match
it. Change a version in a later apply to send new secrets.
